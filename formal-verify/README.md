# formal-verify

実装コードを事実上の仕様 (de-facto 仕様) とみなし、機械検査で「実装が主張している仕様」と「暗黙に決めている挙動」を炙り出す形式手法の skill。有限・決定的な判定ロジックや、冪等性・再実行・順序・crash 復帰が論点のバッチ処理を対象に、AS-IS 挙動を機械検査で確定する。

## やること

3 段で進める。

1. 吸い出し (extract) — コードから宣言された仕様と暗黙の挙動を分けて抜く
2. 形式化して反例探索 (refute) — 主張を純関数モデルにし、全入力・全順序で機械に攻撃させる
3. 突き合わせ (reconcile) — 出た反例をドメインに問い、意図なら仕様化・意図でないならバグに落とす

検査は 2 層。層 1 は同値類の全列挙、層 2 は実行ライフサイクルの TLA+ モデル検査で、全列挙は deno、モデル検査は tlc で行う。最終成果物は証明の山ではなく台帳 (実装の主張・機械検査の結果・ドメインへの確認質問の 3 列) で、反例はバグ報告であると同時に認識合わせの起点になる。

## 発動する場面

- 有限・決定的な判定ロジック (validation・分岐) の検証
- 冪等性・再実行・順序・crash 復帰・二重適用が論点のバッチ処理の挙動確定
- spec docs が無い・あてにならないレガシー機能の AS-IS 起こし
- バグ調査での暗黙挙動の炙り出し
- クロス境界のデータ契約 (フォーマット・enum・単位の合意) の確認

## 対象外

- 確率的・統計的性質 (期待値・分布)
- UI・画面挙動の検証 (画面操作・シナリオ試験は本 skill の対象外)
- 分岐の無い薄い CRUD (列挙する判定ロジックが無い)
- 性能・ボトルネック調査
- 既に単体テストで全ケース網羅済みの領域
