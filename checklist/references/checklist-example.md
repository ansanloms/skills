## 検証

生成したリリースノート (docs/releases/<version>.md) を、書き終えた直後に検査する。

判定・報告は checklist skill に従う。checklist skill が導入されていない環境では、本節の項目を ○/×/対象外で自己点検し、× の該当箇所と根拠、対象外の理由とともに報告へ含める。

### 形式

1. `[critical]` ファイル名がリリースの version (vX.Y.Z) と一致している。
2. `[critical]` 見出し構成が「変更点/破壊的変更/既知の問題」の順で欠落なく揃っている。
3. markdown の lint が指摘を出さない。判定: `deno task lint docs/releases/<version>.md` の終了コード 0 で ○、1 で ×、2 以上は実行不可として対象外。見ないもの: リンク先の実在 (形式 4 が読解で判定する)。
4. 本文中のリンク先 (issue・PR の URL) がすべて実在するリリースの成果物を指している。

### 内容

1. `[critical]` 記載された変更点がすべて対象リリースのコミット履歴に対応している。履歴に無い変更を書いていない。
2. 破壊的変更に移行手順が添えられている。
3. 変更点の記述が利用者視点 (何ができるようになったか) で書かれ、内部実装の用語だけで終わっていない。
